# 算法正确性与复杂度

写出能通过几个样例的代码并不等于算法正确；测出一次运行很快，也不等于它面对更大输入仍然合适。
算法题的完整回答至少包含两部分：为什么结果一定正确，以及资源消耗怎样随输入规模增长。

## 先说明为什么正确

以 Two Sum 为例。暴力搜索枚举所有数对，因此不会漏解；哈希表方案则在扫描过程中保存已经见过的值。

```python
def two_sum(numbers: list[int], target: int) -> tuple[int, int] | None:
    seen: dict[int, int] = {}

    for index, value in enumerate(numbers):
        complement = target - value
        if complement in seen:
            return seen[complement], index
        seen[value] = index

    return None
```

关键不变量是：进入第 `index` 轮时，`seen` 恰好记录了此前元素的“值 → 下标”。因此找到
`complement` 时，两个下标一定不同；如果扫描结束仍没找到，那么每个候选数对都已经被覆盖。

## 数量级比常数更重要

暴力方案最多检查 `n(n-1)/2` 个数对，属于 O(n²)；哈希方案平均扫描一次并做 O(1) 查询，
时间是 O(n)，额外空间是 O(n)。

拖动输入规模时，关注两条曲线之间越来越大的垂直距离。输入从 100 增长到 500，只扩大 5 倍；
线性操作量也约扩大 5 倍，而平方操作量约扩大 25 倍。

### 为什么忽略常数和低阶项

`3n² + 20n + 8` 在 n 足够大时由 `n²` 主导，所以记作 O(n²)。大 O 描述的是增长上界，
不是精确秒数，也不意味着 O(n) 的实现对任何小输入都一定更快。

常见复杂度从慢增长到快增长大致为：

```text
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)
```

其中 O(log n) 常见于每轮把搜索空间缩小一半的二分查找；高效比较排序通常是 O(n log n)。

## 时间和空间需要一起看

哈希表方案用额外内存换取更少的重复搜索。面试中不要只报“优化到 O(n)”，还应说明：

- 时间复杂度：平均 O(n)，依赖哈希查询平均 O(1)；
- 空间复杂度：最坏 O(n)，用于保存此前元素；
- 返回哪一组答案：当前实现返回扫描时遇到的第一组；
- 重复值如何处理：先查再存，能正确处理 `[3, 3]` 和目标 `6`。

如果内存极其受限，可以先排序再用双指针，时间 O(n log n)、额外空间取决于排序实现；但要保留
原下标就需额外处理。不存在脱离约束的“永远最佳方案”。

## 最好、平均与最坏情况

复杂度需要说明讨论的是哪种情况。线性查找最好 O(1)、最坏 O(n)；哈希查询通常说平均 O(1)，
最坏可能退化；快速排序的平均和最坏复杂度也不同。

摊销分析则把偶发昂贵操作分摊到一系列操作上。list `append()` 偶尔需要扩容和复制，但连续追加
n 次的总成本仍是 O(n)，所以单次追加常称摊销 O(1)。

## 二分查找的不变量

二分查找不是记住 `mid = (left + right) // 2`，而是维护“答案若存在，一定仍在候选区间”。
闭区间和半开区间都可行，但边界更新必须与定义一致：

```python
def binary_search(values: list[int], target: int) -> int:
    left, right = 0, len(values)  # [left, right)
    while left < right:
        middle = (left + right) // 2
        if values[middle] < target:
            left = middle + 1
        else:
            right = middle
    if left < len(values) and values[left] == target:
        return left
    return -1
```

该版本实际寻找第一个“不小于 target”的位置，因此也能自然扩展到左右边界问题。前置条件是输入
按相同规则有序。

## 栈、队列与遍历顺序

括号匹配使用栈，是因为最近打开的括号必须最先关闭；广度优先搜索使用队列，是因为先发现的层要先
扩展；深度优先搜索则使用递归调用栈或显式 stack。

选择数据结构时应先说顺序不变量，而不是只说“这题模板用栈”。Python 中队列优先使用
`collections.deque`，避免 list 头部 `pop(0)` 的 O(n) 移动。

## 动态规划从状态定义开始

动态规划适合具有重叠子问题和最优子结构的问题。完整说明通常包含：

1. 状态代表什么；
2. 状态如何转移；
3. 初始条件；
4. 计算顺序；
5. 最终答案位于哪个状态；
6. 是否能压缩空间。

斐波那契的 `dp[i] = dp[i-1] + dp[i-2]` 只依赖前两个状态，因此空间可从 O(n) 压缩到 O(1)。
但复杂业务 DP 应先保留清晰状态表，确认正确后再做空间优化。

## 递归复杂度与调用栈

递归需要同时计算调用次数和每层工作量。二叉递归可能产生指数级调用；分治排序通常产生
`T(n) = 2T(n/2) + O(n)`，结果为 O(n log n)。Python 没有尾递归优化，深递归还会触发递归深度
限制，迭代版本往往更适合生产输入。

## 基准测试回答另一类问题

复杂度分析预测增长趋势；`timeit`、性能剖析和真实压测衡量具体实现。两者不能互相替代。

```python
from timeit import timeit

elapsed = timeit(
    "two_sum(data, 9999)",
    globals={"two_sum": two_sum, "data": list(range(10_000))},
    number=100,
)
print(elapsed)
```

可靠的基准应固定输入、预热运行环境、重复测量并报告分布，同时确认没有把数据构造或 I/O
误算进被测逻辑。微基准很适合比较两个纯函数，不足以代替服务端到端负载测试。

## 如何验证算法而不只靠样例

除了典型样例，还应验证：

- 空输入、单元素、重复值和全相同值；
- 已排序、逆序和极端不均匀分布；
- 目标不存在或答案不唯一；
- 大输入是否符合复杂度预期；
- 属性不变量，例如排序后有序且元素多重集合不变。

属性测试可以用参考实现做差分，也可以只检查数学不变量。性能断言应避免脆弱的毫秒阈值，更适合
检查操作次数、输入规模趋势或超时上界。

## 常见误区

### 两层循环一定是 O(n²)

不一定。双指针虽然可能写成嵌套结构，但每个指针总共只移动 n 次，整体仍可能是 O(n)。
复杂度要数操作次数，不能只看缩进层级。

### 哈希表操作永远是 O(1)

通常说的是平均或摊销复杂度。极端冲突、扩容和恶意输入会影响实际成本；完整回答应带上限定词。

### O(n) 一定优于 O(log n)

只比较符号不够，还要确认 n 的含义、前置条件、常数、内存和调用频率。一次性小输入可能更适合
简单实现；热路径或大规模输入才更需要增长率优化。

## 面试时怎么表述

> 我用 `seen` 维护“此前出现的值到下标”的映射。每轮先查补数再记录当前值，这保证不会使用同一
> 元素两次。每个元素只处理一次，哈希查询平均 O(1)，所以时间 O(n)、额外空间 O(n)。
> 相比 O(n²) 的枚举，它用内存换时间。

这个回答同时覆盖方案、不变量、正确性、复杂度和取舍，比只报一个大 O 更完整。
